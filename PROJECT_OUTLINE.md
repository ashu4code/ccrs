# HT-CGRF — Project Outline

Internal tooling for an **HT (High Tension) Consumer Grievance Redressal Forum**: electricity
consumers log grievances against their distribution company, cases are escalated through a
Regional Manager to a Competent Authority, and every step is recorded in an audit trail.
Built on Laravel 13 (PHP 8.3+) with a session-authenticated JSON API.

## 1. Purpose

Give the Forum a transparent, trackable complaint lifecycle:

- Consumers submit grievances against their `consumer_number` (electricity account) records.
- Regional Managers triage complaints **raised within their own region** and escalate them.
- Competent Authorities adjudicate only the cases escalated specifically to them.
- Every state transition is captured in the `complaint_actions` audit trail.

## 2. Roles

| Role (`App\Enums\UserRole`) | Scope | Capabilities |
| --- | --- | --- |
| `Consumer` | Own complaints only | Register complaints, view own queue/case |
| `RegionalManager` (`regional_manager`) | All complaints whose `region` matches theirs | View region queue, forward `submitted` complaints to a same-region authority |
| `CompetentAuthority` (`competent_authority`) | Complaints escalated specifically to them | View assigned queue, resolve assigned `forwarded` complaints |

Roles live on `users.role` (string column cast to the backed enum) and are enforced twice,
deliberately ("prevent authority bypassing"):

1. the `role:` middleware alias — `App\Http\Middleware\EnsureUserHasRole`, registered in
   `bootstrap/app.php`; and
2. in-controller `abort_unless()` checks in `GrievanceController` as a second wall.

## 3. Workflow

```
Consumer                        Regional Manager                      Competent Authority
--------                        ----------------                      -------------------
  register() ── 201
    status: submitted (default)
    level:  regional_manager (default)
    ticket: ELEC-XXXXXXXX (auto)
        │
        └──────────► forwardToAuthority() ── 200
                       status: submitted → forwarded
                       level:  regional_manager → competent_authority
                       sets regional_manager_id + competent_authority_id
                       (target CA must share the complaint's region)
                           │
                           └──────────► resolveGrievance() ── 200
                                          status: forwarded → resolved
                                          resolved_at: timestamp
                                          allowed only for the assignee
```

- **Statuses** (`ComplaintStatus`): `submitted` → `forwarded` → `resolved`.
- **Levels** (`ComplaintLevel`): `regional_manager` → `competent_authority`.
- **Categories** (`ComplaintCategory`): `billing`, `meter`, `load`, `connection`, `supply`, `other`.

Every transition:

- runs inside `DB::transaction()` with a `lockForUpdate()` re-read of the complaint row, so
  concurrent forwards/resolutions cannot double-process a case (they fail with 409), and
- appends a `complaint_actions` row: `action`, `from_status`/`to_status`,
  `from_level`/`to_level`, `user_id` (actor), `competent_authority_id` (when relevant),
  optional `comment`, timestamps.

Ticket numbers (`ELEC-` + random suffix, collision-checked) are generated by the model's
`static::creating` boot hook on first save; the database's unique index is the final guard.

### Rejection matrix

| Attempt | Result |
| --- | --- |
| Unauthenticated request | 401 |
| Consumer calls forward / resolve | 403 (role middleware) |
| Regional Manager forwards a complaint outside their region | 403 |
| Regional Manager forwards an already-processed complaint | 409 |
| Competent Authority resolves a complaint escalated to someone else | 403 |
| Competent Authority resolves an unforwarded / already-resolved complaint | 409 |
| Manager tags a Competent Authority from another region | 422 |
| Missing or invalid input (fields, category, target authority exists w/ right role) | 422 |
| Range/`Rule::enum` violations on `category` | 422 |

| Path | Purpose |

| `app/Enums/UserRole.php` | Role enum (`Consumer`, `RegionalManager`, `CompetentAuthority`) |

| `app/Models/ComplaintAction.php` | Audit-trail model (complaint, actor, authority relations) |

| `app/Http/Controllers/GrievanceController.php` | Unified controller: `register`, `forwardToAuthority`, `resolveGrievance`, `index`, `show` |
| `app/Http/Controllers/AuthController.php` | `login` (throttled), `logout`, `me` |
| `app/Http/Resources/ComplaintResource.php` | Complaint JSON representation (embeds people/actions when loaded) |
| `app/Http/Resources/ComplaintActionResource.php` | Audit entry JSON representation |
| `app/Http/Resources/UserResource.php` | User summary (also embedded as `UserResource::summary()`) |
| `routes/web.php` | Route definitions (session guard, CSRF via the `web` group) |
| `bootstrap/app.php` | `role:` middleware alias registration; JSON exception rendering |
| `app/Providers/AppServiceProvider.php` | `login` rate limiter (5/min per email+IP); lazy-loading prevention |
| `database/migrations/` | `users` role/region; `complaints`; `complaint_actions` |
| `database/factories/` | `UserFactory` role states; `ComplaintFactory` (`forConsumer`, `forwardedBy`) |
| `database/seeders/DatabaseSeeder.php` | Demo accounts (see §6) |
| `tests/Feature/GrievanceTest.php` | 14 feature tests incl. the full denial matrix |

Status and routing level are **not mass-assignable** — `Complaint::$fillable` covers only the
consumer-supplied fields; the controller sets `status`, `current_level`, and the two FKs explicitly.

## 5. API surface

Session-based JSON API on the `web` middleware group:

- Clients send the session cookie, `Accept: application/json`, and a CSRF token header
  (`X-XSRF-TOKEN`) for state-changing requests.
- Login is rate-limited to 5 attempts per minute, keyed by email + IP.
- Complaint routes use implicit route-model binding (`{complaint}`).

| Method | Path | Guard | Action |
| --- | --- | --- | --- |
| GET | `/login` | — | 401 JSON fallback (named route `login`, keeps redirects valid) |
| POST | `/login` | `throttle:login` | `AuthController@login` |
| POST | `/logout` | auth | `AuthController@logout` |
| GET | `/me` | auth | `AuthController@me` |
| GET | `/complaints` | auth | `GrievanceController@index` — role-scoped queue |
| POST | `/complaints` | auth + `role:consumer` | `register` — create complaint (201) |
| GET | `/complaints/{complaint}` | auth | `show` — owner or same-region staff |
| POST | `/complaints/{complaint}/forward` | auth + `role:regional_manager` | `forwardToAuthority` |
| POST | `/complaints/{complaint}/resolve` | auth + `role:competent_authority` | `resolveGrievance` |

`register` input: `consumer_number`, `category`, `subject`, `description`, optional `region`
(falls back to the consumer's profile region; 422 when neither has one). Forward/resolve accept an
optional `comment` (≤ 5000 chars) recorded in the audit trail.

## 6. Setup & running

```sh
composer setup   # install deps, create .env, key:generate, migrate, npm build
composer dev     # dev server at http://localhost:8000
composer test    # full PHPUnit suite
```

- Dev database: MySQL (`ht_cgrf` on `127.0.0.1:3306`, WAMP) — see `README.md`.
- Tests run on SQLite `:memory:` per `phpunit.xml`.

## 7. Roadmap (deferred phases)

1. Hearings & scheduling — hearing calendar, notices to consumer and licensee, minutes.
2. Document attachments — per-case uploads with validated mime/size.
3. Notifications — email/SMS on registration, escalation, resolution.
4. Dashboard & reporting — KPIs (received/resolved/pending, aging buckets), monthly/quarterly
   compliance reports for the State Electricity Regulatory Commission, Excel/PDF export.
5. Ombudsman escalation tracking — appeal records and outcomes post-`resolved`.
6. Frontend dashboard UI — role dashboards over the existing JSON API.
